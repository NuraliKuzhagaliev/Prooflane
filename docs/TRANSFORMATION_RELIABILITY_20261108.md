# Надёжность: реализация и проверка 8 ноября 2026

Автор этого прохода — отдельный исполнитель backend-направления. Изменялись `prooflane/case_api.py`, новые `prooflane/operations.py` и `prooflane/strict_json.py`, CLI `scripts/verify_receipt.py`, тесты и этот отчёт. Product-insights и производительность реализовывались другим исполнителем; их результаты не записаны как собственная реализация этого прохода.

## Наблюдения до изменений

- `POST /api/cases` и `/variants` выполнялись синхронно без идентификатора операции. Потеря HTTP-ответа не позволяла клиенту однозначно найти выполненный запрос; новый POST мог создать повторный запуск.
- Один глобальный `mutation_lock` держался во время всей операции изменения кейса, включая вызов модели и контейнера. Долгая альтернатива одного дела блокировала изменение диапазонов другого дела.
- Реальный локальный TestClient принял изменённый текст действительного пакета с двумя конфликтующими ключами `case_sha256`: HTTP 200, `passed=true`. Обычный `json.loads` оставлял последнее значение. Это неоднозначность файла, а не демонстрация подделки правильного вычисления с другим hash.
- Гипотеза об ошибке Unicode не подтвердилась: имя с изолированным surrogate вернуло HTTP 422 без отражения исходной строки. `UnicodeEncodeError` наследует `ValueError`, который уже обрабатывает Pydantic. Исправление существующего корректного поведения не засчитывалось как улучшение.

## Отбор решений

| Вариант | Польза и соответствие продукту | Сложность / риск | Критерий приёмки | Решение |
|---|---|---|---|---|
| F1: owner-scoped идентификатор операции и восстановление результата | Повторное открытие результата после обрыва без дополнительного AI-вызова | Средняя; важно не обещать exactly-once у внешнего провайдера | Дубликаты последовательные/конкурентные не создают второй run; другой payload отклоняется; чужая сессия не видит статус | Реализовано |
| F2: блокировка отдельного кейса | Одна медленная работа не блокирует независимое дело | Низкая/средняя; сохраняются global slots и CAS revision | Диапазон второго дела обновляется во время заблокированной альтернативы первого, то же дело получает 409 | Реализовано |
| F3: однозначный JSON верификатора API и CLI | Один загруженный файл не имеет двух трактовок одной claim | Низкая; старые корректные пакеты должны продолжать проходить | Конфликтующие и вложенные duplicate keys отклоняются до вычислений; обычный пакет принимается | Реализовано |
| F4: полноценный многопроцессный job scheduler | Асинхронные длительные задачи и масштабирование | Высокая; новая эксплуатационная инфраструктура | Несколько workers, leases, повторные доставки, restart/kill тесты | Отложено: текущий сервис использует один application worker |
| F5: автоматические повторные обращения к модели после timeout | Возможно снизить ручное восстановление | Высокий риск повторного платного запроса и скрытого неоднозначного результата | Провайдер должен поддерживать доказуемую дедупликацию каждого запроса | Отклонено для этого цикла; статус восстанавливается без повторного исполнения |
| F6: постоянное хранение источников и токена в browser storage | Восстановление редактируемого черновика после закрытия браузера | Риск раскрытия документов/секретов на общем устройстве | Отдельная модель угроз, согласие и управление удалением | Отклонено; для recovery достаточно UUID операции и существующей session cookie |
| F7: межсессионный перенос кейса по публичной ссылке | Упростить совместную проверку | Меняет модель доступа к исходным финансовым данным | Scoped sharing, отзыв доступа, тесты отсутствия утечки | Отложено; переносимый пакет остаётся явным экспортом |

Это три самостоятельных исправления по направлению F. Восстановление активного экрана после reload, новые exports и оформление интерфейса здесь повторно не засчитываются.

## Контракт F1

- `POST /api/cases` и `POST /api/cases/{id}/variants` принимают необязательный `request_id` в формате lowercase UUID. Без него прежний контракт сохраняется.
- SQLite сначала резервирует `(owner, request_id)`. В таблице находятся hash параметров, scope, timestamps, status и ссылки на case/run. Сырые источники, имя дела, причины исключений и operator token в эту таблицу не записываются. `operator_token` не входит в fingerprint.
- Повтор с тем же scope и параметрами: pending → HTTP 202 + `Retry-After: 2`; завершённый → уже существующий case/run без исполнения. Идентификатор с другими параметрами или другим endpoint → HTTP 409.
- `GET /api/operations/{request_id}` возвращает только запись текущей session: `{operation:{id,status,case_id?,failed_run_id?,http_status,error?}}`. Чужая/истёкшая запись → 404. Статус GET не вызывает модель или Docker.
- При завершённом повторе возвращается **текущая версия того же дела**, а не замороженная копия первоначального HTTP-ответа. До четырёх альтернатив и immutable baseline по-прежнему проверяются обычным путём.
- При старте одного application worker незавершённые записи сверяются с уже сохранённым case/вариантом. Подтверждённый commit отмечается completed; остальные — interrupted с явным сообщением. Автоматического повтора программы нет. Вариант сохраняет request ID во внутренней записи для сверки короткого окна между commit и записью статуса; экспорт receipts сохраняет прежний контракт.
- Срок 24 часа; предел 2 000 записей сервера и 120 на owner. После истечения срока прежний key больше не является гарантией дедупликации. Внешний провайдер может принять запрос, даже если его ответ потерян; реализация предотвращает повтор приложения по тому же живому key, а не доказывает exactly-once исполнение у провайдера.
- Для несколько application workers нужен отдельный протокол leases; текущая startup-сверка рассчитана на имеющийся однопроцессный сервис. Общее ограничение двух исполнений и контейнерная изоляция не расширялись.

## Контракт F2/F3

Реестр активных блокировок ограничен 128 ключами `(owner,case_id)` и удаляет ключи после операции. Нет растущего кеша неактивных Lock. Блокировка того же кейса и optimistic revision CAS сохранены; глобальные slots фактического исполнения не изменены.

`load_evidence_json` использует `object_pairs_hook`, отклоняющий повтор ключа в любом JSON object, а также нечисловые NaN/Infinity. API и CLI используют один парсер. Предел 8 MiB остаётся. Ошибка не отражает потенциально чувствительный duplicate key. Проверка структуры/арифметики/хеша по-прежнему выполняется после однозначного разбора, без исполнения кода из пакета.

Критическое интеграционное замечание передано frontend-исполнителю: если интерфейс сначала делает `JSON.parse`, а затем `JSON.stringify` файла, неоднозначные ключи исчезают до API. Поэтому браузер должен отправлять **исходный текст** пакета; синтаксическая проверка клиента допустима, нормализация — нет. Браузерный отрицательный контроль должен проверять этот путь отдельно.

## Фактические проверки

Команда `.venv/Scripts/python.exe -m pytest -q tests/test_operations.py tests/test_cases.py --basetemp <unique-path>` дала **21 PASS**, одно существующее предупреждение Starlette.

Полная регрессия после согласованной backend-интеграции product-insights и performance дала **175 PASS**, одно предупреждение, 6.56 s. [Лог](../artifacts/transformation-20261108/reliability-pytest.txt). Это локальные маршруты FastAPI/SQLite с явно обозначенными doubles; не доказательство нового реального обращения к Vultr или настоящей контейнерной изоляции.

Новые проверки включают потерю create-ответа и owner-scoped recovery, повтор с изменённым токеном без его сохранения, конкурентный duplicate POST, variant replay после изменения revision, failed execution replay, restart-reconciliation, прерывание и TTL, межкейсную конкуренцию, лимит lock registry, неоднозначный JSON в API/CLI, вложенные duplicate keys трёх artifact schemas и сохранённый безопасный отказ Unicode при recovery key.

Read-only ревью `handoff_csv` и `review_brief` другого исполнителя: сопоставление canonical/source row использует bindings; исключённые записи выгружаются без выдуманной цены/variance; текстовые формулы CSV нейтрализуются; Markdown-источники экранируются; exports остаются session-owned и прямо сообщают, что включают исходные данные. Критических дефектов в этих просмотренных путях не найдено. Это не пользовательское исследование и не полная оценка произвольного spreadsheet renderer.

Public HTTP, browser recovery и физический обрыв соединения на новой версии — проверяются владельцем общего релиза отдельно. Реальный вызов модели в этом проходе не выполнялся.

## Источники, которые повлияли на реализацию

Все ниже открыты 8 ноября 2026; внешние snippets не копировались.

- [Stripe, Idempotent requests](https://docs.stripe.com/api/idempotent_requests): request key, сверка параметров, окно хранения и отличие идемпотентности от обычного повтора. Здесь используется собственный формат body `request_id`, не заявляется совместимость со Stripe.
- [SQLite, Transaction](https://www.sqlite.org/lang_transaction.html): короткая `BEGIN IMMEDIATE`-резервация перед побочным эффектом, без удержания write transaction во время AI/Docker.
- [Python 3.13, JSON decoder](https://docs.python.org/3.13/library/json.html#repeated-names-within-an-object): стандартный decoder сохраняет последнее повторное имя; `object_pairs_hook` даёт возможность отклонить неоднозначность, сохраняя лимиты размера.
