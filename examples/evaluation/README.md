# Независимые примеры CSV

Все данные синтетические. Ожидания в `cases.json` рассчитаны вручную и не генерируются функцией `summarize` приложения. Два режима проверяются отдельно: reference и фиксированный рецепт в настоящем Docker. Это не оценка качества модели или доказательство размещения на Vultr.

| Файл | Расчёт billed / положительной разницы | Находки |
|---|---|---|
| `no-variance.csv` | `2×10 + 3×7.50 = 42.50`; разница `0.00` | Нет |
| `decimal-prices.csv` | `3×0.30 + 2×0.10 = 1.10`; `3×(0.30−0.10) = 0.60` | Запись 2 |
| `duplicate-ids.csv` | `12 + 2×8 + 3 = 31.00`; `2 + 2×1 = 4.00` | Записи 2 и 3, один invoice ID |
| `quoted-multiline.csv` | `2×12.34 + 3×2 = 30.68`; `2×2.34 + 3×1 = 7.68` | Записи 2 и 3, независимо от физических переводов строки |
| `untrusted-text.csv` | `2×8.75 + 4 = 21.50`; `2×0.50 = 1.00` | Запись 2; Unicode/HTML-подобный текст и инструкции в notes остаются данными |
| `bom-whitespace.csv` | `2×2.50 + 4×0.75 = 8.00`; `2×0.50 + 4×0.25 = 2.00` | Записи 2 и 3; BOM, пробелы, пустая физическая строка |
| `large-amount.csv` | `999999×99999999.99 = 99999899990000.01`; `999999×0.01 = 9999.99` | Запись 2; стресс-пример, не реалистичный счёт |
| `positive-only.csv` | `15 + 2×3 + 2 + 1 = 24.00`; `5 + 4 + 1 = 10.00` | Записи 2, 3, 4; отрицательная разница не вычитается |
| `invalid-negative-price.csv` | Отрицательная цена | HTTP 422 |
| `invalid-fractional-quantity.csv` | Дробное количество | HTTP 422 |
| `invalid-extra-column.csv` | Лишняя запятая без кавычек | HTTP 422 |
| `invalid-price-precision.csv` | Больше двух десятичных знаков | HTTP 422 |

Под source record понимается номер CSV-записи, где заголовок — 1. Переводы строки внутри кавычек и пустые физические строки не увеличивают номер записи.

## Автоматический прогон

Сначала запустить приложение и Docker по корневому README. Из корня проекта:

```powershell
.\.venv\Scripts\python.exe scripts/evaluate_csv.py --output artifacts/evaluation-local.json
```

Ожидается `24/24 passed`, код завершения 0. Проверяются точные значения, каждая находка, фактически возвращённый receipt, совпадение входа/режима/runtime, нулевое число model calls, Docker cleanup и запрет доступа из другой сессии. Ошибка оставляет FAIL в отчёте и завершает скрипт кодом 1. Доступность сервера и Docker обязательна для полного прогона; скрытого перехода к reference нет.

Без Docker можно запустить `--mode reference` (12 случаев); это не подтверждает изоляцию. Для уже развёрнутого и разрешённого сервиса передать его фактический `--base-url https://YOUR_REAL_HOST` и отдельный `--output artifacts/evaluation-cloud.json`. Скрипт отправляет только эти синтетические CSV, создаёт 16 успешных записей за полный прогон и не запрашивает VSI или operator token. Хостинг в отчёте не аттестуется: URL сам по себе не доказывает, что это Vultr.

Вспомогательные unit checks:

```powershell
.\.venv\Scripts\python.exe -m pytest -q --tb=short
node --test tests/test_format.mjs
```

Тест с инструкциями в notes подтверждает обработку данных в фиксированном workflow. Сырые строки здесь не отправляются модели; это не adversarial benchmark модели.
